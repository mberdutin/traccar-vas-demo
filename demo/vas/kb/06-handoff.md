# Постановка VAS и передача разработчику

Это правила нашего демо-процесса, а не требования upstream Traccar.
VAS-project помогает заказчику сформулировать задачу и подготовить draft issue.

Обязательные разделы: проблема и роль пользователя, текущий сценарий,
желаемое поведение, границы изменения, критерии приёмки, ограничения,
источники, открытые вопросы и способ проверки. Для фронтенда указать
desktop/mobile, состояния loading/empty/error и взаимодействие с API.

Артефакты: intake_notes.md, requirements.md, acceptance.md, decisions.md,
issue_draft.md, handoff.json. Согласование постановки и фактическое создание
GitHub issue — разные события. До подтверждённого API-ответа с URL/номером
нельзя писать «issue создана». Целевой адресат — mberdutin/traccar-vas-demo.

Текущий этап подготовки: VAS-project читает базу знаний и пишет постановку.
Инструмент публикации issue с менеджерским ASK будет подключён на следующем
этапе полного прохода. Сейчас результат — готовый draft и передача менеджеру.
Не использовать shell/gh/curl для обхода этого ограничения.

Передача содержит исходный commit, ссылку на обращение заказчика и явно
отделённые факты репозитория от выбранного заказчиком поведения.
